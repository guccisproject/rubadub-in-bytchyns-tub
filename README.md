# Rubadub in Bytchyns Tub — Website

A plain static HTML/CSS/JS website for **Rubadub in Bytchyns Tub**, a pet
boutique in Gadsden, NC selling grooming, bath & spa, comfort, feeding,
apparel, toy, and travel products for dogs and cats. There is **no build
step and no framework** — it's just files you can open, edit, and host
anywhere that serves static files.

## Local development

No build step, no dependencies to install. Just serve the folder with any
static file server, for example:

```bash
# Python (built in on most systems)
python3 -m http.server 8000

# or Node, if you have it
npx serve .
```

Then open `http://localhost:8000` in your browser. Opening `index.html`
directly via `file://` mostly works too, but some browsers restrict
`localStorage`/fetch behavior on `file://` URLs, so a local server is
recommended.

The 14 pages are: Home, About Us, Contact Us, Products & Services,
Galleries, Cart, Checkout, Order Confirmation, Privacy Policy, Shipping
Policy, Refunds & Returns, Cookie Notice, Legal Notice, and Terms &
Conditions.

## Editing products, bundles, and prices

Everything in the catalog lives in **`js/products.js`** — it's the single
source of truth used by the homepage, products page, cart, checkout, and
confirmation page. To add, remove, or reprice something, edit the
`PRODUCTS` or `BUNDLES` array there:

```js
{
  id: 'gt-01',                 // unique, used as the cart line key — don't reuse ids
  name: 'Slicker Brush Deluxe',
  category: 'grooming-tools',  // must match a slug in CATEGORIES
  price: 14.50,
  description: '...',
  image: 'images/products/gt-01.svg', // <-- swap this to a real photo, see below
},
```

Bundles work the same way but also list the `items` (product ids) they
include, so the site can show how much a customer saves versus buying
those items individually.

`js/products.js` was originally generated by a small script
(`gen_assets.py`, not part of the shipped site) that also produced the
placeholder SVG art — you don't need that script for day-to-day editing,
just edit the arrays directly.

## Swapping in real product photography

Every product and bundle has a single `image` field pointing at a
placeholder SVG illustration (e.g. `images/products/gt-01.svg`). To use a
real photo instead:

1. Drop your photo into `images/products/` (JPG, PNG, or WebP all work).
2. Change that product's `image` value in `js/products.js` to the new
   filename, e.g. `images/products/slicker-brush-deluxe.jpg`.

Do the same for the homepage hero (`images/brand/hero.svg`), the logo
(`images/brand/logo.svg`), category icons (`images/icons/*.svg`), and
gallery tiles (edit the `GALLERY_ITEMS` array at the top of
`js/gallery.js`, which lists each tile's image path and caption).

## Cart, checkout & taxes

- The cart is stored in the browser's `localStorage` (key
  `rubadub_cart_v1`) — no backend required.
- Shipping is a flat **$6.95** under a **$60** subtotal, and **free** at
  $60 or above. Adjust `SHIPPING_FLAT_RATE` / `FREE_SHIPPING_THRESHOLD` in
  `js/cart.js`.
- Sales tax uses an approximate **6.75%** combined rate (North Carolina's
  4.75% state rate plus a typical county rate) — **the business owner
  should confirm the exact combined state + county (+ any local transit)
  rate for their actual filing address with the NC Department of
  Revenue** before going live. This is called out in a comment right
  above `SALES_TAX_RATE` in `js/cart.js`.
- Checkout validates all shipping/contact fields and, for card payments,
  runs a Luhn check plus expiry/CVC format checks — all client-side only.

## Going live with real payments (Stripe or similar)

Checkout does **not** currently talk to any payment processor or bank.
Card numbers are validated for format only (Luhn check), and no charge is
ever attempted. Orders are captured, stored locally, and shown on the
confirmation page so you can build and test the full flow before wiring
up real payments.

There is exactly **one function** to change when you're ready to go live:
`processPayment()` in `js/checkout.js`. It's clearly marked with a comment
block explaining what to do:

1. Add your payment processor's client-side SDK (e.g. Stripe.js) to
   `checkout.html`.
2. Collect a payment method/token with that SDK instead of (or alongside)
   the raw card fields already on the page.
3. Replace the body of `processPayment()` with a call to **your own
   backend**, which creates the actual charge/PaymentIntent server-side
   (a static site like this one cannot safely hold a secret API key, so a
   small server or serverless function is required for this step).
4. Resolve with `{ status: "paid", transactionId }` on success (or reject
   with a user-facing error) — the rest of the checkout flow (saving the
   order, redirecting to `confirmation.html`) needs no other changes.

## Deployment

This is a static site, so it can be hosted anywhere that serves plain
files:

- **Netlify** — drag-and-drop the folder in the Netlify dashboard, or
  connect the git repo and set the publish directory to the project root
  with no build command.
- **Vercel** — import the repo as a project with no framework/build step
  (or "Other" preset), output directory = project root.
- **GitHub Pages** — push to a repo and enable Pages for the branch
  (root directory), or use a `gh-pages` branch/action.
- **Any static host** (S3 + CloudFront, Cloudflare Pages, a plain Apache/
  Nginx server, etc.) — just copy the files up.

No environment variables or server-side configuration are required for
the site to run in its current (pre-payment-integration) state.
